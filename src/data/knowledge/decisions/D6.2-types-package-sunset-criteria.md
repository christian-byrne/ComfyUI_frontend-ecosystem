# ADR-D6.2: `@comfyorg/comfyui-frontend-types` Sunset Criteria

**Status**: PROPOSED (not ACCEPTED — pending Phase B telemetry implementation
and extension-api gap closure)
**Date**: 2026-05-13
**Related**: D6 (parallel-paths migration), D6.1 (entry-point shape),
D9 (strangler-fig phases), P2 (extension-api package)

## Context

`@comfyorg/comfyui-frontend-types` is a load-bearing piece of the v1
ecosystem:

- ~6,854 npm downloads/month (39,341/year), with daily peaks tied to
  frontend releases — i.e. real CI consumption, not curiosity traffic.
- Referenced by **314+ public GitHub repos** including the official
  `Comfy-Org/ComfyUI-React-Extension-Template` (the canonical starter
  Comfy ships to recommend new extension authors), `rgthree/rgthree-comfy`
  (★3k+), `AIDC-AI/ComfyUI-Copilot`, `drawthings.ai/draw-things-comfyui`,
  and dozens of TypeScript-flavoured custom node packs.
- Published lockstep with every frontend release via
  `release-draft-create.yaml → publish_types → release-npm-types.yaml`.
  Cost is <2 minutes per release; fully automated and idempotent.
- Latest version `1.45.6`. Stable on the 1.x line for the entire frontend's
  npm history.

The new `@comfyorg/extension-api` (P2 / PR #12143) ships an intentionally
**narrower v2-only surface**. It deliberately omits `ComfyApp`, `ComfyApi`,
`ComfyNodeDef`, `apiSchema` DTOs, `DOMWidget`, and the `Window.app` ambient
augmentation that v1 consumers rely on. Per the deprecation analysis
(`research/architecture/types-package-deprecation-analysis.md`), the two
packages are **complementary, not equivalent**: ~10 symbols overlap (shell
UI types, identity helpers — already routed via re-export stub per P2),
~20 v1-only symbols have no v2 target.

Per D6 we are at **Phase A** (both APIs ship, no warnings). D6 Phase D
(removal) is gated on telemetry-that-doesn't-exist-yet AND <5% v1 usage AND
12–24 months elapsed since Phase C. CONTEXT.md notes "0 of our ICPs use
ComfyUI without custom nodes" — breaking the long tail without measurement
would be reckless.

This ADR defines the **explicit, all-must-be-met gates** for moving
`@comfyorg/comfyui-frontend-types` from Phase A status-quo into a sunset
sequence. It does NOT authorize sunset today. It establishes the bar.

## Decision

`@comfyorg/comfyui-frontend-types` keeps publishing untouched. Sunset
proceeds **only when ALL of the following gates are met**, in order:

### Gate 1 — Telemetry exists and is collecting

Privacy-preserving instrumentation distinguishes v1 from v2 extension
activations across the live ecosystem.

- Concrete instrument: `window.comfy.__extensionApiVersion` (or
  equivalent) recorded at each registration, aggregated server-side or
  via opt-in beacon. Shape and infra deferred to a separate planning
  doc — currently absent from the codebase.
- Must produce a defensible monthly v1-vs-v2 activation rate, not a
  download proxy. Download counts mix CI traffic, mirror caches, and
  template scaffolding that may never run.
- Reference: D6 Part 2 ("Phases A → B → C can ship without telemetry.
  Only D blocks on it.") and D6 Q3 (open).

### Gate 2 — `@comfyorg/extension-api` absorbs OR explicitly disowns every v1-only export

Maintain a checklist (below; updated as work lands) covering every export
currently in `src/types/index.ts`. Each row resolves to one of:

- **Absorbed** — covered by an equivalent v2 surface in
  `@comfyorg/extension-api`.
- **Disowned** — explicit decision that v2 will not provide an equivalent;
  documented migration alternative.
- **Pending** — work outstanding; gate not yet satisfied for this row.

**Sort hint: Prioritize absorption (or explicit Disownment with migration
recipe) in descending consumer-count order.** The cheap fix is not to absorb
surfaces alphabetically or by ADR ordinal; it is to clear the highest-traffic
consumer paths first so the long tail of small extensions can migrate against
already-stable v2 hooks. Concretely, the v2 surface should land — in this
order — for: `nodeCreated` lifecycle (77) → `onConfigure` lifecycle (56) →
`beforeSerialize`/`beforePrompt` hook for `graphToPrompt` (15, but
CRITICAL) → canvas-event hooks covering S3.C1 (38) → `graph.beforeChange`
listener equivalent for undo-batching consumers (12) → the remaining S2.N*
node-prototype hooks. Only after the top ~5 surfaces above are stable in
`@comfyorg/extension-api` should `Window.app` move toward Disowned-with-
migration-recipe status.

Gate 2 is satisfied only when **every row reads Absorbed or Disowned**, with
no Pending entries.

### Gate 3 — Published migration guide

A first-class migration guide lives at `docs/extensions/migration-v1-to-v2.md`
on docs.comfy.org with worked examples for **the top 10 most-imported v1
surfaces** (ranked by GitHub code-search frequency at the time of writing
the guide; expected to include `ComfyExtension`, `ComfyApp.registerExtension`,
`ComfyNodeDef`, `Window.app`, `DOMWidget`, `ComfyApi.queuePrompt`,
`ComfyApi.fetchApi`, the shell-UI types, and the `apiSchema` DTOs).

Each worked example must show:

1. The v1 import + usage as it appears in real custom-node code today.
2. The v2-equivalent (or explicit "no equivalent — here is the workaround").
3. A side-by-side diff suitable for copy-paste migration.

### Gate 4 — Co-existence soak

After Gates 1–3 are simultaneously met, hold for a **minimum 12-month
co-existence window** during which:

- Both packages publish on every release.
- `@comfyorg/comfyui-frontend-types` carries NO deprecation marker yet.
- Telemetry (Gate 1) shows **sustained <5% v1 activation rate** across at
  least the final 3 months of the window.

The 5% threshold matches D6 Part 2 and conventional long-tail cutoffs
(Chrome use-counter sunsets, Node.js LTS removal). 12 months is the
floor; the D6 Part 2 reference timeline of "18–24 months" remains the
practical expectation.

### Gate 5 — Deprecation announcement → 6-month warning window → removal

Once Gates 1–4 are all met:

1. **Announce deprecation** in a release-notes post, the migration guide,
   and a pinned GitHub Discussion. Add `"deprecated": "Use
   @comfyorg/extension-api"` to the published `dist/package.json` (via
   `scripts/prepare-types.js`).
2. **6-month warning window**: publish releases continue, README carries
   prominent deprecation banner, console warning fires once per page load
   for any extension that imports symbols sourced from
   `@comfyorg/comfyui-frontend-types`.
3. **Final removal**: stop running `release-npm-types.yaml`. Last published
   version remains on npm indefinitely (no unpublish). README points to
   the migration guide.

Total realistic path: **24+ months** from first telemetry to npm
publication halt.

## Consequences

- ✅ Honors the D6 commitment to telemetry-gated sunset; refuses to break
  314+ public repos on a guess.
- ✅ Explicit checklist (Gate 2) prevents "we forgot about `Window.app`"
  surprises during sunset.
- ✅ Workflow cost is <2 min/release in the meantime — negligible carrying
  cost for the safety it buys.
- ✅ Decoupled from PR #12143 / P2 scope discipline. P2 introduces v2;
  this ADR governs v1 retirement separately.
- ⚠️ Long sunset path (24+ months realistically). Two packages to
  document and publicize during the entire window.
- ⚠️ Gate 1 (telemetry) does not exist today and has no owner. Without
  someone planning that work, sunset never starts. Tracked as D6 Q3.
- ⚠️ Gate 2 checklist will need to be revisited as new v1-only surfaces
  are accidentally added (e.g. someone exporting a new symbol from
  `src/types/index.ts`). Add a CI check or AGENTS.md note that any new
  export here also requires a Gate 2 row.

## Alternatives Considered

| Option                                       | Why rejected                                                                                                                                                                                                                                                                |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Immediate removal** (delete `release-npm-types.yaml`, stop publishing) | Breaks 314+ public repos and the official React-extension template at the next release. Removes the `Window.app` ambient augmentation v1 extensions depend on. Direct contradiction of D6 Phase D criteria. Catastrophic ecosystem breakage. |
| **Keep forever, no sunset plan**             | Drift risk between v1 and v2 surfaces grows unbounded. Workflow eventually breaks under maintenance neglect. Comfy team carries permanent dual-publish cost with no exit ramp. Worse than this ADR's explicit-gates approach by exactly the cost of writing this ADR.       |
| **Deprecate now without telemetry gates**    | Pressures consumers to migrate to a v2 package that doesn't yet cover their needs (`ComfyApp`, schema DTOs, `Window.app`). Without telemetry we have no way to know when "<5% usage" is reached, so any deprecation date would be arbitrary. Violates D6 Part 2 explicit "Phase D blocks on telemetry."    |
| **Stack a deprecation PR on top of #12143**  | Out of scope for #12143 (introduces v2 package). Mixes two ecosystem-affecting decisions in one PR, contrary to scope-discipline guidance in CONTEXT.md and `AGENTS.md` rule #8.                                                                                          |
